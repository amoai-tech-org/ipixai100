## Collision warning (parallel with 832)

**Do not** introduce a shared TypeScript enum like:

```ts
type OnboardingStatus =
  | "draft" | "materializing" | "crawl_queued" | "crawling"
  | "analyzing" | "awaiting_approval" | "approved" | "ready" | "failed";
```

That **conflates three different SSOT layers**:

| Layer | Owner ticket | Real values |
| --- | --- | --- |
| `onboarding_sessions.status` | **IPI-832** | `draft` \| `materialized` only |
| `brands.intake_status` | existing DB + **IPI-835** wiring | enum above (`draft_ready`, `crawl_running`, …) |
| Mastra/run UI phase | **IPI-834/835** presentation | derived from intake + crawl rows — not a new DB enum |

**Shared contract to lock before parallel coding (minimal):**

```ts
// IDs only — no fake unified status enum
type OnboardingSessionId = string; // uuid
type BrandId = string;
type OrganizationId = string;
type CrawlId = string;
type IntakeDraftId = string;

// Session status — IPI-832 owns
type OnboardingSessionStatus = "draft" | "materialized";

// Brand pipeline — DB owns; 834/835 consume, do not rename
type BrandIntakeStatus = Database["public"]["Enums"]["brand_intake_status"];
```

Evidence fields for DNA claims belong in **JSON Schema SSOT**, not in session status.
